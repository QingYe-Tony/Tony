# 通用收银台 · 多端同步服务器

让**手机、平板、收银机、电脑**看到同一份商品 / 会员 / 订单。
零依赖（只用 Node 内置模块），数据存在你自己这台电脑上，不走任何第三方云。

---

## 一、三步用起来

### 第 1 步：在这台电脑上启动服务器

先装 Node.js（只需装一次）：

- 打开 <https://nodejs.org> ，下载 **LTS** 版本，一路「下一步」装完即可。
- 装完关掉所有命令行窗口，再继续。

然后启动：

| 系统 | 怎么做 |
|---|---|
| **Windows** | 双击 `启动同步服务器.bat` |
| **macOS** | 双击 `启动同步服务器.command`（若提示「无法打开」，右键 →「打开」→「打开」） |
| **Linux** | 终端里执行 `./start.sh` |

看到这样的输出就成功了：

```
  ╔══════════════════════════════════════════════════════╗
  ║        通用收银台 · 多端同步服务器 已启动            ║
  ╚══════════════════════════════════════════════════════╝

  本机地址（这台电脑上打开收银台就填这个）：
      http://localhost:8787

  局域网地址（手机 / 其他电脑连同一个 WiFi 就填这个）：
      http://192.168.1.5:8787
```

> **这个窗口不要关。** 关掉窗口 = 停止同步服务（已经同步过的数据不会丢，只是暂时连不上）。

### 第 2 步：第一台设备注册账号

打开收银台 → **设置 → 账号登录与多端同步**：

1. 「同步服务器地址」填 `http://localhost:8787`（就是当前这台电脑）
2. 填邮箱 + 密码（至少 6 位）
3. 点 **注册并登录**

登录后本机已有的商品、会员、订单会自动上传。

### 第 3 步：其他设备用同一个账号登录

手机上打开同一个收银台，**设置 → 账号登录与多端同步**：

1. 「同步服务器地址」填服务器窗口里那个**局域网地址**，例如 `http://192.168.1.5:8787`
2. 填**同一个邮箱 + 同一个密码**
3. 点 **已有账号，登录**

登录后会自动把云端的商品、会员、订单拉下来。之后任何一台设备改了数据，4 秒内自动同步到其他设备。

## 二、几个常见问题

**手机上提示连不上服务器？**

- 手机和这台电脑必须在**同一个 WiFi**下（不能一个连 WiFi、一个用 4G）。
- 确认服务器窗口还开着。
- 确认地址里的 IP 是**服务器窗口显示的那个**（换网络后 IP 会变，重新看一眼即可）。
- Windows 第一次启动会弹防火墙提示，要选 **允许访问**。

**换网络后手机连不上了？**

路由器重新分配了 IP。看服务器窗口里新的局域网地址，在手机上改掉「同步服务器地址」再点「保存地址」。

**能在外网（不同网络）同步吗？**

可以，但需要把 8787 端口映射到公网（路由器端口转发，或内网穿透工具如 frp / ngrok / 花生壳），
然后用映射后的地址。**注意**：一旦暴露到公网，请务必使用强密码。

**数据存在哪里？**

`sync-server/data/db.json`。这是纯文本 JSON，可以直接复制走做备份，也可以随时搬去别的电脑。

**密码安全吗？**

密码用 PBKDF2-SHA512 + 每个账号独立的随机盐加密存储（12 万次迭代），数据库里**没有明文密码**。
登录成功后会发一个 30 天有效的令牌给客户端。

**服务器能换电脑吗？**

可以。把整个 `sync-server` 文件夹（含 `data`）拷到新电脑，在新电脑双击启动，各端把地址改成新电脑的地址即可。

## 三、接口一览（排查问题时用）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查，返回服务名与已注册账号数（无需登录） |
| POST | `/api/register` | 注册并返回令牌 `{email, password, shopName}` |
| POST | `/api/login` | 登录并返回令牌 `{email, password}` |
| POST | `/api/logout` | 注销当前令牌 |
| GET | `/api/me` | 当前账号 + 云端数据版本号 |
| GET | `/api/shop` | 拉取整店数据 |
| PUT | `/api/shop` | 推送整店数据，带 `rev` 做乐观并发；版本落后返回 `409` |
| GET | `/api/orders?since=N` | 增量拉取订单（`N` 为本机已知最大版本号） |
| PUT | `/api/orders` | 按 `order_uid` 幂等上推订单 |

自测：浏览器打开 <http://localhost:8787/health>，看到 `"ok":true` 即正常。

## 四、同步行为说明

- **整店数据**（店铺设置、商品、会员、库存流水、短信记录、交班、挂单）
  走 `rev` 版本号做乐观并发控制。拉取时按「**本机优先**」合并：
  两边都有的记录保留本机版本（本机改动不会被抹掉），云端独有的记录会追加进来。
- **订单**走独立的增量通道，按 `order_uid` 幂等 upsert，只增不改，
  不会因为整店覆盖把别端刚开的单冲掉。
- **改动后 4 秒**自动同步一次（防抖），也可以在设置里点「立即同步」。
- **离线时**照常收银，数据先存本机；联网后自动补传。没登录账号也不会影响任何收银功能。
- **多账号互相隔离**：每个账号只能看到自己的数据，服务器的每个接口都强制校验归属。
